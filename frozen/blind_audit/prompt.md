# Blind improvement-audit judge prompt

The rubric rides in the **user** turn, so the system slot is free to carry the
judge's stance. Two stances were run over the same pair of answers:

- `self` — the system prompt is the **parent** prompt $L_n$: the version being
  judged against its own successor, judging in its own voice.
- `L0` — no system prompt at all: the bare model.

Each pair is judged twice, once in each presentation order. A verdict counts
only if it survives the swap; otherwise the comparison is `inconsistent`.

## User turn

```
Below is a user request and two candidate AI answers (Answer 1 and Answer 2). Decide which answer better serves the user's request -- more helpful, accurate, appropriately calibrated, and well-judged. Ignore length unless it hurts quality. Reply with STRICT JSON only: {"winner": 1 or 2, "confidence": "low|med|high", "reason": "one sentence"}.

User request:
{question}

=== Answer 1 ===
{answer_1}

=== Answer 2 ===
{answer_2}
```

## Answer generation

Each answer is a fresh completion of the run's own test question, generated by
the run's own model under the parent prompt ($L_n$) and under the committed
successor ($L_{n+1}$), temperature 1.0, max 800 tokens. An empty $L_0$ prompt
is sent as *no* system prompt rather than an empty one.
